## 1. 三行心法

1. **一份報告 = 一個 `報告內容.md` ＋ 旁邊一個 `data/` 資料夾。** 其他什麼都不用。
2. **圖表用「宣告」寫，不寫程式**：在正文裡放一個 ```` ```figure ```` 區塊，
   說清楚資料在哪、要畫哪種圖、欄位叫什麼，引擎就畫出來。**區塊放在哪，圖就出現在哪。**
3. **版型不歸妳管**：版心、配色、字級、互動、目錄都鎖死了。妳只負責把內容填對。

```
我的報告/
  報告內容.md          ← 全部的文字、圖表宣告、數字都在這裡
  data/
    dau.csv
    tbl_prepost.csv
    values.json（選用）
  out/                 ← build 出來的單檔 HTML
```

## 2. `報告內容.md` 的骨架

**版型順序是寫死的：標題 → 前言 → 結論 → 建議 → 各章 → 附錄。**
md 裡誰先誰後不影響排版，但照這個順序寫比較好讀。

````markdown
---
title: 遊戲名－這份在看什麼
subtitle: 一句話副標
period: 2026-05-01~2026-06-30，斷點 06-01，前後各 30 日
population: 全站活躍玩家，n＝約 12 萬人日
source: 表名 / notebook 名
produced: 2026-09-16
byline: 數據分析一組 | Lena
note_base: "母體：全站活躍玩家（當日至少開一局）｜口徑：前段 05-01~05-31、後段 06-02~06-30，斷點當日不計｜n：前 648,213 人日／後 601,940 人日｜區間：2026-05-01~2026-06-30"
values:
  前段平均: 41.2
  後段平均: 37.4
---

## 前言

第一段會排成大字 lede，寫 2～3 句「這份在看什麼、掉多少、下面怎麼展開」。

第二段開始是一般內文。空一行才換段。

## 結論

- [dn] 平均由 {{v:前段平均}} 降到 {{v:後段平均}}（[[fig_line]]）。
- [up] 新客占比上升（[[fig_s100]]）。
- 星期效應校正後結論不變。

## 建議

- [立即] 先對帳斷點 ±3 天的版更／活動／埋點變更清單
  預期影響：決定這份分析成不成立；口徑是第一順位要排除的假說

## 現象確認：真的掉了

本章結論：水位在斷點後整段下移，不是單日雜訊。

這裡寫一段說明：為什麼要看這張圖、跟上一章的關係。

```figure
key: fig_line
type: line
title: 指標隨時間的走勢
...（宣告內容見第 4 節）
```
判讀：斷點後水位下移，波動幅度沒變大。

## 附錄

### 圖表色彩規則

紅＝上升、綠＝下降，每個變化數字都帶 ▲▼ 與正負號；類別一律中性藍。
熱圖與檢定底色是單一色相的亮度階，只編碼強度、不編碼方向。
````

### 檔頭欄位

| 欄位 | 必填 | 放什麼 |
|---|---|---|
| `title` `subtitle` `period` `population` `source` `produced` `byline` | ✔ | 七個都不能空 |
| `note_base` | 建議 | **全篇共用**的母體註腳，會出現在每一張圖表底下（＝備註第四列） |
| `values:` / `values_file:` | | 數字 key，見第 6 節 |
| `disclaimer` `badge` | | 示意假資料標記。**正式報告整行刪掉** |
| `appendix: false` | | 這份不要附錄。宣告了就**不可以**再寫 `## 附錄`（會報錯） |
| `hints: false` | | 不印圖表旁的互動提示小字。**排序與 tooltip 照樣能用**，只是不印字 |

### 章節的四段結構

每一章固定：**本章結論 → 一段說明 → 圖表區塊 → 判讀**。

| 寫法 | 效果 |
|---|---|
| `## 標題` | 一章，自動編號（`前言`／`結論`／`建議`／`附錄`／`本版說明` 是保留字，不算章） |
| `### 子節` | H3 |
| `本章結論：` | 小標底下粗體帶紅邊那一句，**一章一句** |
| ```` ```figure ```` / ```` ```table ```` | 插入圖／表，編號與備註自動帶出 |
| `判讀：` | 圖表底下那句話，**必須緊接在區塊收尾 ``` 的下一行**（中間可空行，不能夾別的段落） |
| `[[key]]` | 引用圖表 → 自動變「圖 2-1」超連結。**每張圖表至少要被引用一次**（QA 第 4 項會擋） |

### 結論與建議的固定語法

```markdown
## 結論
- [dn] 這條講下降 → 卡片上緣綠色
- [up] 這條講上升 → 卡片上緣紅色
- 不寫方括號 → 灰色（中性）

## 建議
- [立即] 動作寫在這一行（時程標籤可寫 立即／短期／長期）
  預期影響：這一行不能省
```

`## 結論` 裡也可以直接放 ```` ```table ````／```` ```figure ````（編號是 `表 C-1`／`圖 C-1`）。
**條狀卡片是預設、不能拿掉**，表格是加在卡片之外的；區塊寫在第一張卡片前面就排在卡片上方。

### 區塊裡的 YAML 子集寫法

```
key: 值                    # 冒號後面要有空格
清單: [A, B, C]
巢狀:
  - {col: raw, name: 原始}   # 一項一行
  - col: p90                # 或多行
    name: p90
```

- 縮排**只能用空格**。
- 值裡有 `,` `:` `{` `}` `[` `]` 或前後有空格 → **用雙引號包**：`legend_title: "|t|"`、`n: "648,213"`。
- 純數字自動變數字，`true`／`false` 變布林，`2026-06-01` 是文字。
- 區塊裡不能再出現一行只有 ``` 的行（會被當成收尾）。

## 3. 備註四列規範（v1.6 硬規則）

**每一張圖表底下固定四列，不多不少。** 前三列是 `defs` 的三個鍵，第四列是母體註腳。
`defs` 多寫一個鍵（例如再加 `母體:`）`build.py` 直接報錯，`qa_html.py` 第 17 項再查一次。

> 正本在 `references/圖表與數值宣告格式.md` §3.1（含七條反例）。下面是摘要版。

| 列 | 寫在哪 | **要放什麼** | **不要放什麼** |
|---|---|---|---|
| **維度** | `defs.維度` | **分群／軸是怎麼切的**：底台是什麼、cohort 怎麼分、x 軸一格是一天還是一週、「新客」怎麼定義、交叉表是什麼 × 什麼 | 把欄名唸一遍（「維度：底台」等於沒寫）；指標的算法 |
| **指標** | `defs.指標` | **難理解的指標定義與算法**：分子分母、單位、pp 還是 %、平滑窗幾天、分位數怎麼來、檢定方法與門檻 | 大家都懂的再解釋一次（「DAU＝日活躍用戶」）；母體與時間區間 |
| **著色** | `defs.著色` | **這張圖表「特有的」**視覺編碼：底色代表什麼、灰底列是什麼、空白格是什麼、粗框／虛線是什麼、色階越深代表什麼 | **全報告通用的規則**（紅漲綠跌、▲▼ 帶正負號、類別用中性藍）——那些在附錄「圖表色彩規則」講一次就夠 |
| **母體** | 檔頭 `note_base` ＋ 區塊 `note_extra`（或 `note` 整句覆寫） | **母體 ＋ 口徑 ＋ n ＋ 時間區間，四樣都要** | 只寫「玩家」「全體」；把某一張表特有的口徑寫進 `note_base`（那是全篇共用的） |

### 反例 → 改法

| 反例 | 問題 | 改成 |
|---|---|---|
| 每張表的著色都寫「紅＝上升、綠＝下降」 | 通用規則複製十次，真正該講的被擠掉 | 附錄講一次；這列只留「灰底列＝本表主指標 mean」 |
| 「母體：玩家」 | 沒有區間、沒有 n、沒有口徑 | 「母體：全站活躍玩家（當日至少開一局）｜口徑：前段 05-01~05-31、後段 06-02~06-30，斷點當日不計｜n：前 648,213 人日／後 601,940 人日」 |
| 「維度：底台」 | 把欄名唸一遍 | 「維度：三個底台（盲注級距）× 前段／後段」 |
| `defs` 多一個 `母體:` 鍵 | 變五列，跟第四列重複 | 母體只寫在 `note_base`／`note_extra` |
| 這張表特有的口徑寫進 `note_base` | 會出現在**每一張**圖表底下 | 寫進該區塊的 `note_extra` |
| 著色寫「無」／「不適用」 | 讀者會一直找顏色的意思 | 「中性藍單色，不編碼漲跌；沒有底色與粗框」 |

### 引擎會自動補、妳不用寫的

- 宣告 `sig` 時自動補「底色著色為經統計檢定有顯著差異，方向為左右（／上下）著色」；
  帶強度值時再自動補深淺說明。要自己寫就 `sig.note: false`。
- `note_base` 與 `note_extra` 之間的 `｜` 由程式加，**不要自己在 `note_extra` 開頭再打一個**。
- cohort／星期×小時／顯著度熱圖的「空白＝…」、直方圖「分位線是估算」那幾句畫在圖上，不用寫進備註。

> `examples/` 裡 v1.5 以前的樣張是**舊寫法**（每張圖的著色都複述紅漲綠跌），**不要照抄那部分**。
> `sig-shade-demo` 是照新規範寫的，要抄抄它。

## 4. 14 種圖表各一段最小可跑範例

共用規則：`key`／`type`／`title`／`defs`（三列）必填；`aria` 強烈建議寫（給螢幕閱讀器與 QA）；
`data:` 路徑相對於 `報告內容.md`；`height` 不寫用各型預設，寬固定 1120 不要改。

### 4.1 `line` — 時間序列折線

csv：`date,指標A`（第一欄 x，其餘每欄一條線）

````
```figure
key: fig_line
type: line
title: 折線：指標隨時間怎麼走
data: data/line.csv
x: date
xfmt: md
unit: 分
series:
  - {col: 指標A, name: 指標A, color: s1}
break: 2026-06-16
break_label: 斷點 06-16
vlines:
  - {at: 2026-06-05, label: 活動開始}
  - {at: 2026-06-16, label: 版本更新, color: red, icon: warn}
aria: 折線示意：指標A 在 06-16 斷點後由約 100 降到約 92。
defs:
  維度: 日期（30 日）
  指標: 示意指標A（分）
  著色: 藍線＝指標A；墨色虛線＝一般事件、紅虛線＋警示 icon＝需注意的事件
```
判讀：斷點後水位下移（[[fig_line]]）。
````

常用加料：

- **分位帶**：`- {kind: band, id: band, lo: p25, hi: p75, label: p25~p75, color: band, order: 2}`
- **`break` vs `vlines`**：`break` 只能一條，會畫灰帶，而且 `values:` 的 `seg: pre/post` **靠它定義**；
  `vlines` 可多條，只是「這天發生了某件事」的標記，**不切段、不影響計算式**。兩個可以並用。
- **`icon: warn`（v1.6）**：只能 `warn`，畫在線的下端。一張圖最多 2～3 個，全標等於沒標。
- **指定刻度**：`xticks: [2026-06-01, 2026-06-16, 2026-06-30]`（值要是 x 欄真的有的值；
  與 `xtick_every` 只能擇一）。

### 4.2 `waterfall` — 瀑布

資料可以直接寫在 `items:` 裡（不用 csv）。

````
```figure
key: fig_wf
type: waterfall
title: 瀑布：總變化拆成各段貢獻
ylab: 分
unit: 分
nd: 2
items:
  - {name: 前段水位, kind: level, value: 41.20}
  - {name: 效應甲, kind: delta, value: -1.20}
  - {name: 效應乙, kind: delta, value: -2.60}
  - {name: 後段水位, kind: level, value: 37.40}
aria: 瀑布示意：前段 41.20，效應甲 -1.20、效應乙 -2.60，後段 37.40。
defs:
  維度: 拆解項：前段水位 → 效應甲 → 效應乙 → 後段水位
  指標: 各段貢獻（分）；兩段相加＝總變化
  著色: 中性灰＝水位柱、綠＝下降的變化柱；y 軸自 0 起未截斷
```
判讀：效應乙佔多數（[[fig_wf]]）。
````

- **`level` 會核對恆等式**：「起點 ＋ 前面各 delta ＝ 這個值」，差超過一個單位就報錯。
  真的只是尾差，把終點改成 `kind: subtotal`（值由程式算）。
- 最多 12 段。段多時 `kind: subtotal` 可以插中繼水位點。

### 4.3 `stacked100` — 100% 堆疊橫條（組成前後對照）

csv：`label,sub,A 段,B 段,C 段`（段的欄加總 ＝ 1 或 100）

````
```figure
key: fig_s100
type: stacked100
title: 100% 堆疊橫條：組成前後對照
data: data/stacked100.csv
label: label
sub: sub
segments: [A 段, B 段, C 段]
colors: [s3, s2, s1]
deltas: auto
delta_unit: pp
aria: 組成前後對照：A 段由 22% 升到 30%，C 段由 47% 降到 41%。
defs:
  維度: 前段／後段 × 三段組成
  指標: 各段占該期總量的比例（%）；變化以 pp 表示
  著色: 同色系深→淺＝C 段→A 段
```
判讀：A 段占比上升（[[fig_s100]]）。
````

`deltas: auto` ＝ 剛好兩根條時自動算「▲ +8.0 pp」標在下方。

### 4.4 `ranked` — 貢獻排序橫條（每根拆兩段）

csv：`名稱,段內效應,占比效應`（**剛好兩段**）

````
```figure
key: fig_rank
type: ranked
title: 貢獻排序橫條：誰貢獻最多
data: data/ranked.csv
name: 名稱
parts: [段內效應, 占比效應]
colors: [dn, dn2]
sort: abs
unit: 分
aria: 貢獻排序：群組甲合計 -2.76 分最多，群組丁 -0.20 分最少。
defs:
  維度: 四個群組，依合計絕對值由大到小
  指標: 段內效應 ＋ 占比效應 ＝ 該群組合計貢獻（分）
  著色: 同色系深淺兩段＝段內／占比；本圖全為下降故用綠色系
```
判讀：群組甲貢獻最大（[[fig_rank]]）。
````

合計、占總變化、累積占比由程式算，不要自己抄進 csv。

### 4.5 `bars` — 類別直立柱（含正負）

csv：`類別,偏差值`

````
```figure
key: fig_bars

### 4.6 `retention` — 留存曲線

csv：`day,新客,老客,全體`（第一欄天數位移，其餘每欄一群；**最多 4 條**、**不支援缺值**）

````
```figure
key: fig_ret
type: retention
title: 留存曲線：多群 Dn 留存
data: data/retention.csv

## 5. 表格的各種宣告

### 5.1 最小宣告

csv：`指標,前段,後段,變化`

````
```table
key: tbl_basic
title: 表格：最小宣告
data: data/tbl_basic.csv
columns: [指標, 前段, 後段, 變化]
align: [left, right, right, right]
types: [text, num, num, num]
emph_rows: [1]
defs:
  維度: 指標 × 前後段（每列一個指標）
  指標: 變化 ＝（後 − 前）÷ 前
  著色: 灰底列＝本表主指標；變化欄 ▲▼ 為方向
```
判讀：三個指標中兩降一升（[[tbl_basic]]）。
````

| 欄位 | 說明 |
|---|---|
| `columns` ✔ | 顯示用表頭（欄數要跟 csv 一樣） |
| `align` | `left`／`right`／`center`，預設第一欄 left、其餘 right |
| `types` | `text`／`num`（排序用），預設第一欄 text、其餘 num |
| `emph_rows` | 灰底強調的列號，**從 1 數**（不含表頭） |
| `sortable` | 預設 true；宣告 `rowspan`／`row_groups`／`sig` 上下配對時**自動變 false** |

**cell 可以寫**：純文字、`{{d:-12.1:%}}`（變化 chip，自帶 ▲▼ 正負號）、`{{n:39.05:分}}`、
`{{v:key}}`、`{{warn}}`；要指定排序值寫 `顯示@@排序值`（`<0.001@@0.0005`、`N/A@@`）。
含逗號的 cell 用雙引號包。N=0 標 `N/A`，不要留 0 或空白。

### 5.2 合併格 `rowspan` ＋ 列群組粗線 `row_groups`

csv：`區域,分組,樣本數,平均`（北區 2 列、南區 2 列）

````
```table
key: tbl_span
title: 表格：合併格與列群組粗線
data: data/tbl_span.csv
columns: [區域, 分組, 樣本數, 平均]
align: [left, left, right, right]
rowspan: [1]
row_groups: [2, 2]
defs:
  維度: 區域（2 群）× 分組（每群 2 列）
  指標: 樣本數（人）與平均（分）
  著色: 群與群之間 2px 粗線；第一欄相鄰同值合併成一格；本表固定列序不可排序
```
判讀：北區樣本較多（[[tbl_span]]）。
````

- `rowspan: [1]` ＝ 第 1 欄相鄰**同值**的列合併成一格（空白格不合併）。
  寫多欄是**階層式**：後一欄的合併不會跨過前一欄的分界。
- `row_groups: [2, 2]` ＝ 由上往下 2 列一群、2 列一群，**加總必須等於資料列數**。
- 兩者都綁在列的位置上 → **自動 `sortable: false`**，故意寫 `sortable: true` 會報錯。

### 5.3 檢定底色 `sig`

底色是**中性藍的亮度階**，只說「這兩格差異顯著」；**方向仍然看 ▲▼ 與正負號**（紅綠是漲跌語意，不拿來當顯著）。

**(a) 左右配對（同一列的兩欄），單一階**

```
sig:
  dir: lr
  pairs:
    - {row: 1, a: 2, b: 3}
```

**(b) 上下配對（同一欄的兩列）** — 這種表會**自動關掉排序**

```
sig:
  dir: tb
  pairs:
    - {col: 2, a: 1, b: 2}
    - {col: 3, a: 2, b: 3}
```

**(c) `mark: max`（v1.6）— 只標數值較大的一格**

```
sig:
  dir: lr
  mark: max
  pairs:
    - {row: 1, a: 2, b: 3}
```

比大小優先用該格的排序值（`顯示@@排序值` 的右半），沒寫就從 `{{d:}}`／`{{n:}}` 挖數字。
**讀不出數字會報錯**（`N/A`、`—`、`ns`）→ 補 `顯示@@數值`，或把 `mark` 改回 `both`。

**(d) 深淺三階（v1.6）— 依檢定強度分深淺**

````
```table
key: tbl_sig
title: 表格：檢定底色（左右配對、只標較大格、深淺三階）
data: data/tbl_sig.csv
columns: [指標, A 組, B 組, "|t|"]
align: [left, right, right, right]
sig:
  dir: lr
  mark: max
  scale: "|t|"
  levels: [2.58, 3.29]
  pairs:
    - {row: 1, a: 2, b: 3, v: 5.91}
    - {row: 2, a: 2, b: 3, v: 3.04}
    - {row: 3, a: 2, b: 3, v: 2.12}
defs:
  維度: 指標 × 兩個分組（每列一組左右配對）
  指標: 兩樣本 t 檢定的 |t|（第 4 欄保留原始統計量）
  著色: 階界 2.58／3.29 ＝ p<.01／p<.001；沒上底色＝未達 p<.05
```
判讀：指標一證據最強（[[tbl_sig]]）。
````

| 階 | 色值 | 什麼時候 |
|---|---|---|
| 第 1 階（最淡） | `#d7e3ee` | `v < levels[0]` |
| 第 2 階 | `#b0c8db` | `levels[0] ≤ v < levels[1]` |
| 第 3 階（最深） | `#8baec9` | `v ≥ levels[1]` |

- **`mark` 與深淺是正交的兩件事**：`mark` 決定「哪一格上色」、`scale`／`levels`＋`v` 決定「那一格多深」。
  可以只用一個，也可以併用。
- **`scale` 與 `levels` 都必填，引擎不猜**（同樣是 3.0，`|t|` 是普通顯著、`-log10(p)` 已是 p=0.001）。
  常用兩組：`|t|` → `[2.58, 3.29]`；`-log10(p)` → `[2, 3]`。
- **階數固定三階**，`levels` 給一個或三個切點會報錯。切點要由小到大、非負。
- `v` 一律**非負**（`|t|`／`-log10(p)`／效果量絕對值）；**要分深淺就每一組 `pairs` 都要帶 `v`**，只帶一半會報錯。
- **一組都不帶 `v` ＝ 單一階**（＝v1.5 行為）。
- **階界是絕對門檻，不是這張表的 min／max** → 同一份報告的多張表可以互相比深淺，
  所以請**全篇固定同一組 `scale` 與 `levels`**。
- **原始統計量仍然要留一欄**（`p 值` 或 `|t|`）：黑白影印與色盲的讀者要能從數字讀出同一件事。
- **底色不要上在 `{{d:}}` 變化欄**：紅綠字壓在第 2／3 階底色上對比不足。
- 同一格被兩組配對指到 → 取最深的那一階，不報錯。
- 列號欄號**全部從 1 數、不含表頭**。改了 csv 的列序欄序，記得回頭改 `sig`／`rowspan`／`row_groups`／`emph_rows`。

### 5.4 兩個開關

寫在**檔頭**（不是表格區塊裡）：

```

## 6. 數字 `{{v:key}}` 與行內標記

數字來源兩處，可混用、key 不能重複：

```
---
values_file: data/values.json          # {"key": "值", …}
values:
  斷點: 2026-06-16
  前段人日: "648,213"                   # 含逗號要引號
  前段平均: {fn: mean, fig: fig_line, col: 指標A, seg: pre, fmt: n, nd: 2, unit: 分}
  平均變化率: {fn: pct_change, fig: fig_line, col: 指標A, a: pre, b: post, fmt: d, nd: 1, unit: "%"}
---
```

| `fn` | 算什麼 |
|---|---|
| `mean` `sum` `min` `max` `range` `count` `first` `last` | 一段資料的統計量；範圍用 `seg: pre/post/all` 或 `from`／`to` |
| `diff` | `b − a` |
| `pct_change` | `(b / a − 1) × 100` |

`fmt`：`n`（中性數字 chip，預設）／`d`（變化 chip，自帶 ▲▼ 正負號）／`text`（純文字）。
`nd` 小數位、`unit` 單位（要前置空格寫 `" 分"`）、`comma: true` 千分位。

> `seg: pre`／`post` **要該圖先宣告 `break`**，斷點當日不計入兩段。

### 行內標記

| 標記 | 產出 |
|---|---|
| `{{v:key}}` | 檔頭定義的數字（**推薦**：改資料不會不一致） |
| `{{n:39.1:分}}` | 手寫中性數字 |
| `{{d:-4.7:分}}` | 手寫變化量，自動配 ▼ 綠／▲ 紅與正負號 |
| `{{warn}}` | 警示 icon（inline SVG 紅三角）。**不吃參數**，`⚠` emoji 會被 QA 擋 |
| `!!重點!!` | 重點紅字，**一段最多一處** |
| `[[key]]` | 引用圖表 → 「圖 2-1」超連結 |

**紅綠是方向不是好壞**：紅＝漲／重點、綠＝跌；每個變化數字都帶 ▲▼ 與正負號。

## 7. 產出與自我檢查

```bash
# 產出 HTML（檔名自動用 title）
python3 scripts/build.py --md 報告內容.md --out out/

# 17 項自我檢查 —— 交付前一定要跑，要看到「總結：全部通過」
python3 scripts/qa_html.py "out/遊戲名－這份在看什麼.html"

# 列出所有 {{v:key}} 與圖表 key、目前的值與來源（對數字用）
python3 scripts/build.py --md 報告內容.md --keys

# 列出所有圖表類型與欄位
python3 scripts/build.py --types
```

**寫錯不會產出壞檔案**：解析不過就印「第幾行、什麼問題、提示」、exit 1、**既有 HTML 不動**。
根因（圖表宣告／資料層）會先列，正文層的連鎖錯誤放後面：

```
內容檔解析失敗：/…/報告內容.md
【先修這些：圖表宣告／資料層的根因】
  第 80 行：資料裡沒有 `adjj` 這一欄
           → data/ts_break.csv 的欄位：date、raw、adj、sm
【接著才看這些：正文層，多半是上面造成的連鎖】
  第 147 行：{{v:帶寬前段}} 找不到這個數字 key
           → 是不是要打 `帶寬前`、`帶寬後`？
共 2 個問題；HTML 沒有重新產生，改完再跑一次 build.py。
```

### `qa_html.py` 的 17 項在查什麼

錨點／id 唯一／圖表編號連續／**每張圖表都被引用**／▲▼ 帶正負號／重點紅字每段最多一處／
**零外部資源**／JS 未被竄改／圖有 `role=img`＋`aria`＋`desc`／**紅綠只用在方向**／互動掛勾齊全／
無回跳殘留／備註不反白／目錄一一對應／字級階層／標頭 icon 無 emoji／**備註四列**。

交付前這三項最常紅：**第 4 項**（忘了在正文寫 `[[key]]`）、**第 10 項**（類別用了紅綠）、
**第 17 項**（`defs` 多寫一個鍵）。

## 8. 最常踩的錯與對應的錯誤訊息

> 完整報錯表在 `SKILL.md` 第 6 節。下面是高頻的。

### 備註與 defs

| 看到 | 原因 | 怎麼修 |
|---|---|---|
| ``defs 多了 `母體`——備註只能四列：維度／指標／著色 ＋ 母體`` | `defs` 寫了第四個鍵 | 母體寫進檔頭 `note_base:` 或區塊 `note_extra:` |
| `defs 缺 著色` | 三列不齊 | 補齊 維度／指標／著色 |
| `缺母體註腳` | 沒有 `note`，檔頭也沒 `note_base` | 檔頭加 `note_base:` |
| QA `17 備註四列 FAIL` | 手改過 HTML | 回去改 `報告內容.md` 重 build，不要手改 HTML |

### 資料與欄名

| 看到 | 原因 | 怎麼修 |
|---|---|---|
| ``資料裡沒有 `xxx` 這一欄 → …的欄位：a、b、c`` | `series` 的 `col`／`x` 跟 csv 表頭不一致 | 照提示的欄名改（**一字不差**，含全形半形空格） |
| `data 檔找不到：data/x.csv` | 路徑是相對於 **md 所在資料夾** | 把 csv 放到 md 旁邊的 `data/` |
| ``第 N 列的 `col` 不是數字`` | csv 有單位、千分位或空字串 | 清成純數字；缺值不要留空列 |

### 引用與正文

| 看到 | 原因 | 怎麼修 |
|---|---|---|
| QA `4 正向引用 FAIL：未被引用 [fig-xxx]` | 正文沒有 `[[xxx]]` | 在判讀或結論提到它 |
| `{{v:xxx}} 找不到這個數字 key → 是不是要打 …` | key 打錯或沒定義 | 照建議改，或跑 `--keys` 看全部 |
| ``圖表 `xxx` 宣告了但沒有被放進任何章節`` | 區塊放在前言／建議裡 | 移到章節、附錄或 `## 結論` |
| ``\`判讀：\` 要緊接在 … 收尾 \`\`\` 下一行`` | 判讀前面夾了別的段落 | 移到區塊收尾的下一行 |
| QA `6 重點紅字 FAIL` | 同一段兩個 `!!…!!` | 一段留一處 |

### 區塊語法

| 看到 | 原因 | 怎麼修 |
|---|---|---|
| `對應 { 沒有用 } 收尾` / `縮排…` | 區塊裡 YAML 寫壞 | 值裡有 `,` `:` `#` 用雙引號包；縮排只用空格 |
| `{{fig:xxx}} 這種寫法已停用` | 舊版佔位寫法 | 改成 ```` ```figure ```` 區塊放在那一行 |
| `{{warn:red}} 不吃參數` | 警示 icon 帶了參數 | 就寫 `{{warn}}` |

### 表格與檢定底色

| 看到 | 原因 | 怎麼修 |
|---|---|---|
| ``sig.pairs 第 N 項的 b 9 不是 1~5 的欄號`` | 配對指到表格外 | 列號欄號都從 1 數、不含表頭 |
| ``sig.pairs 第 N 項的 v 是負的（-5.91）`` | 填了帶號 t 值 | 填 `\|t\|` 或 `-log10(p)`；方向看 ▲▼ |
| ``table 的 sig 缺 `scale``` / ``缺 `levels``` | 帶了 `v` 卻沒說是哪種統計量、階界在哪 | 補 `scale: "\|t\|"` 與 `levels: [2.58, 3.29]` |
| ``sig.pairs 第 N 項缺 `v``` | 只有一部分配對帶強度值 | 每組都寫 `v`，或全部拿掉（＝單一階） |
| ``levels 要剛好兩個切點（三階），現在有 3 個`` | 想自己調階數 | 階數固定三階，只給兩個切點 |
| ``levels 要由小到大且不相等`` | 切點寫反 | 小的在前，例 `[2.58, 3.29]` |
| ``sig 宣告了 mark: max，但第 N 列第 M 欄的 'N/A' 讀不出數字`` | 配對格不是數字 | 那一格補 `顯示@@數值`，或 `mark` 改回 `both` |
| `rowspan／row_groups 不能跟 sortable: true 併用` | 想同時要合併格與排序 | 拿掉 `sortable: true` |
| `row_groups 加起來是 7 列，但資料有 6 列` | 群組列數沒對上 | 加總要等於資料列數 |
| QA `11 互動掛勾 FAIL`（表數對不上） | 寫了 `sortable: false` 但沒有 rowspan／列群組 | 讓它可排序，或用 `rowspan`／`row_groups` |

### 圖型限制

| 看到 | 原因 | 怎麼修 |
|---|---|---|
| ``不認得的圖表類型 `xxx``` | type 打錯 | 用那 14 種之一；不合就改成 `table` |
| `分群長條至少要兩條序列` / `最多 3 條序列` | 序列數不對 | 1 欄改 `bars`；>3 拆圖或改表格 |
| ``第 N 列的 `xxx` 是負的——堆疊長條的段不能是負值`` | 絕對量出現負數 | 有正負的量改 `bars`／`grouped` |
| `瀑布最多 12 段` / `啞鈴圖最多 20 組` / `直方圖疊圖最多 2 組` | 拆太細 | 合併成「其他」或拆成兩張圖 |
| ``第 N 項「…」是 level，值 … 與前面各段的累計 … 差 …`` | 瀑布恆等式不成立 | 核對各段正負號；真的只是尾差就把終點改 `kind: subtotal` |
| ``vlines.at `2026-06-31` 不在 x 欄裡`` | 事件日不是資料裡的 x 值 | 照 csv 的 x 值寫（日期格式要一致） |
| `vlines 的 color 只能是 red／ink` / `icon 只能是 warn` | 寫了別的值 | 只有這幾個值 |
| `xticks 與 xtick_every 只能擇一` | 兩個都寫了 | 只留 `xticks` |
| ``{{v:xxx}} 算不出來：選到的範圍有缺值（空白格）`` | 計算式踩到熱圖空白格 | 用 `from`／`to` 限定已完整觀察的範圍 |
| `用 seg: pre 之前，這張圖要先宣告 break` | 計算式用了 pre／post 但圖沒有 break | 圖加 `break: <x 值>`，或改用 `from`／`to` |
| `檔頭寫了 appendix: false，卻還有一節 `## 附錄`` | 兩種都寫了 | 二選一 |
