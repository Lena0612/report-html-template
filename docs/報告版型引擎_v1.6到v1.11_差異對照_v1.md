## 二、逐版做了什麼

### v1.7（2026-09-16）— 兩項新能力，都是「宣告才生效」

**一句話：圖例可以搬到 x 軸下方、結論可以改成純條列，不宣告就跟 v1.6 一模一樣。**

| 改動 | 分類 | 說明 |
|---|---|---|
| `line` 的 `legend: bottom` | 新能力 | 圖例從右側改成 x 軸下方橫排。右邊界 158 → 26（繪圖區寬 +132）、下邊界 +46。**`height` 不會自己加**，要維持原本繪圖區高度就把 `height` 加 46。圖例元素的 class 與 `data-key` 沒變，點一下切換序列照常可用 |
| 檔頭 `conclusion_style: list` | 新能力 | 結論從條狀卡片改成純條列（`<ul class="bul concl-list">`），`　◦ ` 開頭的行變成上一條的子項。**卡片模式下 `◦` 仍然是「上一條寫太長的換行接續」，v1.6 行為一個字沒改**。條列模式下 `[dn]`／`[up]` 只寫進 class、不上色（條列沒有卡片上緣那條色帶） |

兩項都有守門：值寫錯、或第一條就是 `◦`（沒有可掛的主條目）→ 報錯 ＋ 行號 ＋ exit 1 ＋ 不產 HTML。
新增樣張 `examples/charts-demo-7`。

### v1.8（2026-09-16）— 一個真 bug ＋ 兩項新能力 ＋ 一項放寬

**一句話：跌點線的紅色從 v1.4 起就沒生效過，這版才真的紅；另外 defs 不必三列都寫了。**

| 改動 | 分類 | 說明 |
|---|---|---|
| `vlines` 顏色改 inline style | **修正（會改產出）** | v1.4 起用 SVG presentation attribute 給色（`stroke="#c62828"`），但 CSS 有 `.chart .bkline{stroke:var(--ink2)}`。**presentation attribute 在串接裡輸給任何一條 class 規則**，所以紅色從來沒渲染出來，兩條跌點線跟其他事件線一樣是墨灰。（warn icon 的 `<g fill="#c62828">` 沒有 class、沒規則蓋得到，所以三角驚嘆號一直是紅的——肉眼「有紅色」才一直沒被抓到。）改成 inline `style=` 就贏得過 class 規則 |
| `vlines` 的 `label2` | 新能力 | 事件標籤第二行：`label` 慣例寫日期、`label2` 寫事件名，差一個行高、同一個 x，相鄰事件線的標籤才不會左右撞在一起。寫了 `label2` 卻沒有 `label` → 報錯 |
| `conclusion_style: numbered` | 新能力 | 結論條列改 1. 2. 3.（外層 `<ul>` → `<ol>`）。子項補一個 inline `list-style-type:circle` 把 ◦ 釘住，**CSS 一個 byte 都沒改** |
| `defs` 從「剛好三列」放寬 | 新能力 ＋ **語法變更** | 放寬：三列裡挑 1~3 列即可，缺的不報錯。**但同時新增一條限制：寫到的那幾列順序必須是 維度 → 指標 → 著色**。另新增「`defs` 整個空」「寫了 key 卻空值」兩條報錯 |

`themes.py`／CSS／JS 三個 md5 零變動（我實際算過，見第七節）。
影響範圍：只有宣告 `vlines` ＋ `color: red` 的產出會變。

### v1.9（2026-09-17）— 三項新能力 ＋ 必填放寬

**一句話：檔頭三個欄位跟母體註腳都可以不寫了，表格多了欄位群直向粗框，結論區多三個開關。**

| 改動 | 分類 | 說明 |
|---|---|---|
| `subtitle`／`produced` 改選填 | 新能力 | `FM_REQ` 從 7 個減到 5 個（`title period population source byline`）。沒寫 `subtitle` 時 `<p class="subtitle">` **整行不出現**（不是留一個空 `<p>`）；沒寫 `produced` 時資料說明列連它前面那根 `｜` 一起少 |
| 母體註腳改選填 | 新能力 | 以前 `_check_common` 會報「缺母體註腳」，等於逼每個區塊都要有一行母體——同一句印在 25 個區塊底下本來就是雜訊。現在沒有就整塊 `<p class="blk-note">` 不渲染 |
| `note`／`note_extra` 空值 → 報錯 | **語法變更** | 放寬的同時補一條**更嚴**的：寫了 key 卻留空就擋，免得產出一個空殼 `<p class="blk-note"></p>` |
| 孤兒 `｜` 修掉 | 修正 | 沒有 `note_base`、只有 `note_extra` 時，備註會印成 `｜補充…`（開頭掛一根孤兒直線）。修掉 |
| ```` ```table ```` 的 `col_groups` | 新能力 | 欄位群直向粗框，寫法對齊 `row_groups`（`col_groups: [1, 1, 3, 2, 2, 2]`，加總＝欄數）。**只畫群與群之間、最右邊不收線**（欄向本來一條直線都沒有，右緣再收會變成沒有左緣的半框）。**不會關掉排序**——它綁的是欄，排序只重排列。一格同時要檢定底色與直粗框時兩段併進同一個 `style` 屬性 |
| `conclusion_lead: false` | 新能力 | 不印「紅＝漲、綠＝跌，▲▼ 與正負號同步。」那行小字（連同那一行，不留空白） |
| `conclusion_badge: false` | 新能力 | 不印區塊標題右邊那顆「最重要」膠囊。它是 `::after` 的 `content`，**沒辦法被 inline style 蓋掉**，CSS 又凍結，所以唯一的路是不掛 `sec-key` 這個 class；`.sec-key` 另外帶的 4px 紅上框、白底與 icon 紅色用 inline style **原樣補回來**（最終生效值三項完全相同，只有來源從 css 變 inline） |
| `conclusion_box: true` | 新能力 | 結論每一條各自一個灰底區塊；標 `[up]` 的那條紅底紅字（沿用既有 tone 語意，不另發明標記）。`◦` 子項不包框。配 `card` 會報錯 |
| qa 第 17 項判準 | 判準 | 母體註腳「剛好 1 列」→「0 或 1 列」，另**新增：不准出現空殼列**。放寬的是「可以不印」，不是「可以印一個空殼」 |
