# 圖表與數值宣告格式（skill v1.6，2026-09-16）

`報告內容.md` 裡的圖、表、數字都用**宣告**寫，資料放 csv／json，程式（`scripts/figures.py`）讀宣告去畫。
沒有 numpy、沒有 pandas，只有 Python 標準庫。

---

## 1. 總覽

| 東西 | 寫在哪 | 語法 |
|---|---|---|
| 圖 | 章節或附錄正文裡 | ```` ```figure ```` … ```` ``` ```` 區塊；**放在哪，圖就出現在哪** |
| 表 | 同上 | ```` ```table ```` … ```` ``` ```` 區塊 |
| 判讀 | 區塊收尾 ```` ``` ```` 的下一行 | `判讀：一句話` |
| 數字 `{{v:key}}` | 檔頭 `values:`，或 `values_file: data/values.json` | 文字，或 `{fn: …}` 計算式 |
| 文中提到圖表 | 任何句子裡 | `[[key]]` → 自動變成「圖 2-1」超連結 |

一個 key 只能宣告一次、只會出現一次。舊寫法 `{{fig:key}}`／`{{tbl:key}}` 已停用（會報錯並提示改法）。

**v1.4（2026-09-16）新增**：圖表類型 `sigheat`（顯著度熱圖，§4.14）；`line` 多一個 `vlines` 欄位（多條垂直事件虛線，§4.1）。版型、配色、字級、JS、CSS 都沒動。

**v1.7（2026-09-16）新增**：`line` 多一個 `legend` 欄位（`bottom`＝圖例搬到 x 軸下方，§4.1）；檔頭多一個 `conclusion_style`（`list`＝結論改純條列，見 `內容檔格式說明.md` §6）。兩項都是宣告才生效，不宣告時輸出與 v1.6 逐 byte 相同；版型、配色、字級、JS、CSS 都沒動。

**v1.5（2026-09-16）新增**：**沒有新圖表類型**，只加「宣告才生效」的八項能力——

## 掉在分布的哪一段：低分位掉最多

本章結論：分布整段平移下移，低分位掉最多。

只看 mean 分不出「重度玩家流失」與「全體變差」，所以把分位數與 mean 並列看。

  - {col: p90, name: p90, label: p90, color: q, width: 1.2, order: 1}
  - {col: mean, name: mean, label: mean, color: ink, width: 1.8, dash: true, order: 4}

break_label: 斷點 08-12

## 2. 區塊裡的寫法（YAML 子集，`scripts/yamlite.py`）

只支援下面這些，錯了會報「第幾行、什麼問題」：

```
key: 值                        # 一行一個欄位，冒號後要有空格
series:                        # 巢狀：底下縮排兩格
  - {col: raw, name: 原始 mean, color: raw, width: 1.3}   # 一項一行的 {欄位: 值, …}
  - col: p90                   # 或多行寫法
    name: p90
columns: [變數名稱, 上線前, 上線後]                        # 清單
defs:
  維度: …
data: |                        # 區塊文字：底下縮排更深的行全部原樣保留（放 CSV）
  date,raw,adj
  2026-07-16,39.9,39.4
```

規則：
- 縮排只能用**空格**。
- 註解：行首 `#`，或行內「空格 ＋ `#` ＋ 空格」。`#c62828` 這種緊接文字的不算註解，不會被截掉。
- 純數字自動變數字（`1.3`、`400`、`0`），`true`／`false` 變布林；其他都是文字。`07-16`、`2026-08-12` 是文字。
- **值裡有 `,` `:` `{` `}` `[` `]` 或前後有空格時用雙引號包**：`unit: " 分"`、`n: "648,213 user-day"`。
- 以 `{{` 開頭的值視為字面文字（`{{n:39.05:分}}` 這類標記），不會被當成 `{…}` 對應。
- 區塊裡不能再出現一行只有 ```` ``` ````（那會被當成收尾）。

## 3. 圖表區塊共用欄位

| 欄位 | 必填 | 說明 |
|---|---|---|
| `key` | ✔ | 英數／底線／連字號；正文用 `[[key]]` 引用、HTML 錨點用它 |
| `type` | ✔ | `line`／`waterfall`／`stacked100`／`ranked`／`bars`（v1）＋ `retention`／`grouped`／`funnel`（v1.1）＋ `stacked`／`cohort`（v1.2）＋ `hist`／`dumbbell`／`dow_hour`（v1.3）＋ `sigheat`（v1.4）；共 14 種，全部在第 4 節（＋ ```` ```table ```` 共 15 種圖表區塊） |
| `title` | ✔ | 圖標題（編號後面那段）；可含 `{{v:…}}` |
| `defs` | ✔ | 備註的前三列，**只能這三個鍵、缺一報錯、多一個也報錯**：`維度`（分群／軸怎麼切）／`指標`（怎麼算）／`著色`（這張圖表特有的視覺編碼）。第四列「母體」是 `note`／`note_extra` 那一行，不要寫進 `defs`——完整規範見 §3.1 |
| `note` | 二選一 | 母體註腳全文「母體：…｜口徑：…｜n：…」 |
| `note_extra` | 二選一 | 接在檔頭 `note_base` 後面（自動加 `｜`）。兩者都沒有且檔頭沒 `note_base` → 報錯 |
| `aria` | 建議 | 給螢幕閱讀器與 QA 的一句話摘要（含關鍵數字）。不寫用 title |
| `desc` | 選 | `<desc>` 補充（畫法為什麼這樣）。不寫用 aria |
| `hint` | 選 | 圖左下角的操作提示。不寫用各型預設 |
| `height` | 選 | viewBox 高度（px）。寬固定 1120，不要改 |

`title`／`defs`／`note`／`aria`／`desc`／標籤文字裡都可以用 `{{v:key}}`。

### 3.1 備註四列：維度／指標／著色 ＋ 母體（Lena 2026-09-16 15:12 規範）

每張圖表底下**固定四列、不多不少**。前三列是 `defs` 的三個鍵，第四列是母體註腳
（檔頭 `note_base` ＋ 區塊 `note_extra`，或用 `note` 整句覆寫）。多寫一個 `defs` 鍵就變五列，
`build.py` 會擋（`defs 多了 \`母體\`——備註只能四列`），`qa_html.py` 第 17 項再查一次。

| 列 | 來源 | 放什麼 | 不要放什麼 |
|---|---|---|---|
| 維度 | `defs.維度` | **分群／軸是怎麼切的**——看不懂分群的人靠這一列：底台是什麼、cohort 怎麼分、x 軸一格是一天還是一週、「新客」怎麼定義、交叉表是什麼 × 什麼 | 把欄名唸一遍（「維度：底台」等於沒寫）；指標的算法（那是下一列） |
| 指標 | `defs.指標` | **難理解的指標定義與算法**：分子分母、單位、pp 還是 %、平滑窗幾天、分位數怎麼來、檢定方法與門檻 | 大家都懂的指標再解釋一次（「DAU＝日活躍用戶」）；母體與時間區間（那是第四列） |
| 著色 | `defs.著色` | **這張圖表特有的**視覺編碼：底色代表什麼、灰底列是什麼、空白格是什麼、粗框／虛線是什麼、哪個顏色是哪一段、色階越深代表什麼 | **全報告通用的規則**：紅漲綠跌、▲▼ 帶正負號、類別用中性藍——這些在附錄「圖表色彩規則」講一次就夠 |
| 母體 | `note_base` ＋ `note_extra`（或 `note`） | **母體 ＋ 口徑 ＋ n ＋ 時間區間，四樣都要**：誰被算進來、怎麼算、幾人／幾人日、哪一段到哪一段（有斷點就寫斷點與前後天數） | 只寫「玩家」「全體」這種沒有範圍的字；把某一張表特有的口徑寫進 `note_base`（那是全篇共用的，要寫進該區塊的 `note_extra`） |

**引擎會自動補、你不用寫的**（寫了就變重複）：

- 宣告 `sig` 時，備註結尾自動補「底色著色為經統計檢定有顯著差異，方向為左右（／上下）著色」；
  `pairs` 帶強度值時再自動補「｜底色深淺＝\|t\|，越深證據越強（三階：…）」。要自己寫就 `sig.note: false`（§5.1）。
- `note_base` 與 `note_extra` 之間的 `｜` 由程式加，不要自己在 `note_extra` 開頭再打一個。
- cohort／星期×小時／顯著度熱圖的「空白＝…」、直方圖「分位線是估算」那幾句畫在圖上，不用寫進備註。

**常見寫錯（反例 → 怎麼改）**：

| 反例 | 問題 | 改成 |
|---|---|---|
| 每張表的著色都寫「紅＝上升、綠＝下降（▲▼ 與正負號同步）」 | 全報告通用的規則被複製十次，真正該講的（灰底列是什麼、底色是什麼）反而被擠掉 | 附錄「圖表色彩規則」寫一次；這一列只留「灰底列＝本表主指標 mean」 |
| 「母體：玩家」 | 沒有時間區間、沒有 n、沒有口徑，讀者無法判斷這張表能不能跟上一份比 | 「母體：全站活躍玩家（當日至少開一局）｜口徑：前段 05-01~05-31、後段 06-02~07-01，斷點 6/1 當日不計｜n：前 648,213 人日／後 601,940 人日」 |
| 「維度：底台」 | 把欄名唸一遍 | 「維度：三個底台（盲注級距）× 前段／後段」 |
| 在 `defs` 多加一個 `母體:` 鍵 | 變成五列，而且跟第四列的母體註腳講同一件事 | 母體只寫在 `note_base`／`note_extra`（build 會擋） |
| 這張表特有的口徑寫進檔頭 `note_base` | `note_base` 是全篇共用，寫進去會出現在**每一張**圖表的備註下面 | 寫進該區塊的 `note_extra` |
| 著色寫「無」／「不適用」 | 就算沒特別著色也要講清楚，否則讀者會一直找顏色的意思 | 「中性藍單色，不編碼漲跌；沒有底色與粗框」 |
| 著色寫「底色＝顯著」＋ 引擎又自動補一句 | 跟自動補的標準句重複 | 這一列只寫**階界與例外**（「階界 2.58／3.29 ＝ p<.01／p<.001；沒上底色＝未達 p<.05」） |

> `v1.5` 以前的 `examples/` 是舊寫法（每張圖表的著色都複述一次紅漲綠跌），**不要照抄**。
> 唯一的例外是整份關掉附錄（`appendix: false`）的報告：沒有附錄可以講色彩規則，才在著色列補一句。

## 4. 十四種圖表類型（v1 五種 ＋ v1.1 三種 ＋ v1.2 兩種 ＋ v1.3 三種 ＋ v1.4 一種；加 ```` ```table ```` 共 15 種圖表區塊）

### 4.1 `line` — 時間序列折線（可含分位帶）

| 欄位 | 必填 | 說明 |
|---|---|---|
| `data` | ✔ | csv 路徑（相對於 md 所在資料夾）或 `data: \|` 內嵌 |
| `x` | ✔ | 橫軸欄名（文字，通常是日期） |
| `xfmt` | | `full`（預設，原樣）／`md`（`2026-07-16` → `07-16`） |
| `series` | ✔ | 清單，每項一條線或一個帶（下表） |
| `unit` `nd` | | 全圖預設單位（tooltip 用）與小數位；預設 `""`、1 |
| `ylab` | | y 軸標題 |
| `ymin` `ymax` | | 固定 y 範圍（分位帶通常 `ymin: 0`） |
| `xtick_every` | | 每幾個 x 標一個刻度，預設 7（會自動補標最後一個 x） |
| `xticks` | | **指定刻度清單**（v1.5）：`xticks: [2026-05-01, 2026-06-01, 2026-07-01]`，可不等距。值必須是 x 欄裡真的有的值；**指定什麼就只標什麼**（不自動補最後一個）。與 `xtick_every` 只能擇一 |
| `break` | | 斷點的 x 值（要在 x 欄裡）；畫垂直虛線與 ±N 天灰帶 |
| `break_span` `break_label` | | 灰帶半寬（預設 3）、斷點標籤 |
| `reflines` | | 水平參考線清單（下表） |
| `vlines` | | **垂直事件虛線清單**（v1.4，下表）；可多條，與 `break` 並存 |
| `legend` | | **圖例位置**（v1.7）：`right`＝序列名稱標在線的右端（預設，v1～v1.6 行為）；`bottom`＝橫排圖例放 x 軸下方。寫 `bottom` 時右邊界 158→26（繪圖區寬 +132）、下邊界 +46，**`height` 不會自己加**，要維持繪圖區高度就把 `height` 加 46 |
| `height` | | 預設 380 |

`series` 每項：

| 欄位 | 說明 |
|---|---|
| `kind` | `line`（預設）或 `band` |
| `col` | line：資料欄名 |
| `lo` `hi` | band：下緣／上緣欄名（例 p25／p75） |
| `id` | data-key（預設＝col；band 預設 `band`） |
| `name` | 顯示名（tooltip、標註；預設＝col） |
| `label` | 右側直接標註文字（預設＝name；`false` 不標） |
| `color` | 顏色角色（line 預設 s1、band 預設 band） |
| `width` | 線寬，預設 2.2 |
| `dash` | `true` 虛線（mean 慣例用虛線，跟分位數分開） |
| `order` | tooltip 裡的排序（小→上） |
| `unit` `nd` | 覆寫全圖預設 |
| `lo_name` `hi_name` | band 的兩端名字（預設＝欄名） |

`reflines` 每項：

| 欄位 | 說明 |
|---|---|
| `at` | y 值：數字，或計算式 `{fn: mean, col: raw, seg: pre}`（fig 省略＝本圖） |
| `label` | 線上的文字 |
| `color` | 預設 ink |
| `seg` | `pre`（0～斷點前一天）／`post`（斷點後一天～最後）／`all`（預設） |
| `from` `to` | 用 x 值指定範圍（與 seg 二選一） |
| `anchor` | 標籤靠 `start`（預設）或 `end` |

`vlines` 每項（v1.4）：

| 欄位 | 必填 | 說明 |
|---|---|---|
| `at` | ✔ | 事件發生的位置：**x 欄裡的值**（例 `2026-06-02`）。不在 x 欄裡會報「vlines.at `…` 不在 x 欄裡」並印出 x 的頭尾 |
| `label` | | 線旁的事件文字（預設不標）。畫在線右側、圖頂；**宣告 `icon` 時跟著移到圖下方** |
| `color` | | 只能 `red`（`#c62828`，跌點／負面事件）或 `ink`（預設，中性）。留空＝`ink`。其他值報錯 |
| `icon` | | **v1.6 選用**。只能 `warn`：在這條線的**下端**（離 x 軸 7px）畫一個紅色三角驚嘆號，形狀與行內標記 `{{warn}}` 完全相同，顏色跟著 `color` 走（預設紅）。不宣告＝完全沿用 v1.5 的畫法（輸出逐 byte 相同） |

**`icon: warn` 什麼時候用**：這條事件線是「跌點／要讀者停下來看一眼」的那種。Lena 2026-09-16 定案
「斷點要紅虛線＋warning icon、圖標放在圖下方」——所以 icon 與它的標籤都在圖的下緣，
不跟序列、y 軸標題與圖頂的直接標註擠在一起。一張圖建議最多 2～3 個 icon，全部都標就等於沒標。
只有 `warn` 一種形狀，**不吃別的參數**（`icon: warn:red` 會報錯）。

```
vlines:
  - {at: 2026-05-28, label: v9.5 換版}                       # 一般事件：墨色虛線、標籤在圖頂
  - {at: 2026-06-02, label: 6/2 跌點, color: red, icon: warn} # 跌點：紅虛線＋三角驚嘆號在圖下方
```

**`vlines` 與 `break` 的差別**（兩者可以同時用，但語意不同，不要互相冒充）：

| | `break`（v1，單一） | `vlines`（v1.4，可多條） |
|---|---|---|
| 幾條 | **只能一條** | 幾條都可以（建議 ≤ 5，太多會疊在一起） |
| 畫出來是什麼 | 垂直虛線 ＋ **前後 ±`break_span` 天灰帶** ＋ 斷點標籤 | **只有**垂直虛線 ＋ 可選事件標籤，沒有灰帶 |
| 語意 | 「這條線把資料切成 pre／post 兩段」 | 「這天發生了某件事」——純標記，不切段 |
| 有沒有連動 | `values:` 計算式的 `seg: pre`／`post` **靠它定義**；沒宣告 break 就用不了 | **完全不影響計算式**；`seg: pre`／`post` 不會因為它而可用 |
| 什麼時候用 | 改版上線、口徑切換——要比前後 | 活動開始／結束、外部事件、多次小改版 |

要做前後對比就用 `break`；只是想在圖上標「這幾天發生過什麼」就用 `vlines`。
**兩個都用**的情境：`break` 標主要斷點（前後比較），`vlines` 補上同期的幾個次要事件。

### 4.2 `waterfall` — 瀑布（水位 → 變化 → … → 水位；v1.3 起不限 4 段）

```
```figure
key: waterfall
type: waterfall
title: 總變化拆解瀑布（前段 → 組內 → 組成 → 後段）
ylab: 分/人/日
unit: 分
nd: 2
items:
  - name: 前段平均
    kind: level
    value: 39.052
    tip: {期間: 07-16~08-11, n: "648,213 user-day"}
  - name: 組內效應
    kind: delta
    value: -1.2046
    tip: {占總下滑: 25.5%, 讀法: 同一群人玩得比較少}
  - name: 組成效應
    kind: delta
    value: -3.5274
    tip: {占總下滑: 74.5%, 讀法: 低時長族群占 user-day 比重上升}
  - name: 後段平均
    kind: level
    value: 34.32
    tip: {期間: 08-13~09-08, n: "612,470 user-day"}
aria: 瀑布圖：前段平均 39.05 分，組內效應 -1.20 分（占 25.5%），組成效應 -3.53 分（占 74.5%），後段平均 34.32 分。
defs:
  維度: 拆解項：前段水位 → 組內效應 → 組成效應 → 後段水位
  指標: 組內 ＝ Σ w̄ × Δm；組成 ＝ Σ Δw × m̄（慣例 B，兩項相加＝總變化）
  著色: 中性灰＝水位柱、綠＝下降的變化柱（上升會是紅）；y 軸自 0 起未截斷
note_extra: 拆解：慣例 B（中點權重對稱二項）；y 軸自 0 起未截斷
```
```

| 欄位 | 說明 |
|---|---|
| `items` | 二選一（與 `data`）。每項 `name`、`kind`、`value`（數字）、`tip`（tooltip 補充列，鍵值對） |
| `data` | 二選一（與 `items`）。csv：`name,kind,value` ＋ 其餘欄自動變成該柱的 tooltip 列；段多或直接從 notebook 匯出時用這個 |
| `name` `kind` `value` | 只在 `data:` 模式用：指名 csv 的名稱欄／種類欄／數值欄（預設同名欄；沒有 `kind` 欄時第一列與最後一列當 `level`、中間當 `delta`） |
| `ylab` `unit` `nd` | 預設 `""`、`分`、2 |
| `label_every` | `1`（預設，每根變化柱都標數字）或 `2`（隔一根標）。段多標籤會擠在一起時用 |
| `height` | 預設 330 |

`kind` 三種（**v1.3 起有 `subtotal`**）：

| `kind` | 是什麼 | `value` |
|---|---|---|
| `level` | 水位柱（從 0 畫起），通常是起點與終點 | 必填；**第一項以外的 `level` 會核對「起點 ＋ 前面各 delta ＝ 這個值」**，差超過 `nd` 的一個單位就報錯 |
| `delta` | 變化柱（接在前一根的水位上） | 必填，帶正負號 |
| `subtotal` | **中繼水位點**（v1.3）：把前面幾段收成一根水位柱再往下拆 | **可留空，程式算累計**；寫了就核對，不符報錯（第 1 項不能是 subtotal） |

- **段數 v1.3 起不限 4 段，但最多 12 段**（`Waterfall.MAX = 12`）。超過會報
  「瀑布最多 12 段（現在 N 段）」＋提示「把小的變化合併成『其他』，或拆成兩張圖（例如先族群、再因子）」——
  理由是 1120px 版心下 13 段以上柱寬 < 60px，名稱與數字都擠爛，讀不出來。
- 變化柱顏色由正負自動決定（紅漲綠跌）＋ `▲▼` 與正負號，水位柱與中繼柱中性灰。y 軸從 0 起、不截斷（設計決定 12）。
- 名稱太長會自動折成兩行；再長就截斷，完整名稱在 tooltip。
- 恆等式核對是刻意的：**瀑布畫出來就是在宣稱「起點 ＋ 各段 ＝ 終點」**，對不上多半是某段 delta 的正負號或四捨五入。
  真的只是尾差，就把終點那項的 `kind` 改成 `subtotal`（值由程式算）。

### 5.1 `sig` — 檢定顯著的單格底色（v1.5；**v1.6 可依檢定強度分深淺三階**）

檢定有顯著差異的**兩格一起上底色**，讀者一眼看到「哪兩格在比」。底色是**中性藍的亮度階**
（`#d7e3ee`，比照 cohort／顯著度熱圖的單色思路）：**不用紅綠**（紅綠在這版型是漲跌語意），
所以底色只說「這兩格差異顯著」，方向仍然看 `{{d:…}}` 的 ▲▼ 與正負號。

```
sig:
  dir: lr                 # lr＝左右配對（同一列的兩欄）／tb＝上下配對（同一欄的兩列）
  pairs:
    - {row: 1, a: 2, b: 3}    # lr：第 1 列的第 2 欄與第 3 欄
    - {row: 3, a: 2, b: 3}
```

```
sig:
  dir: tb                 # 上下配對
  pairs:
    - {col: 4, a: 3, b: 4}    # tb：第 4 欄的第 3 列與第 4 列
    - {col: 4, a: 5, b: 6}
  note: false             # 選填，預設 true＝自動把標準備註句加到備註後面
```

| 欄位 | 說明 |
|---|---|
| `dir` ✔ | `lr` 左右配對／`tb` 上下配對（Lena 原話「方向為上下（或左右）著色」） |
| `pairs` ✔ | 每一組顯著的配對一項。`lr` 寫 `{row: 列號, a: 欄號, b: 欄號}`；`tb` 寫 `{col: 欄號, a: 列號, b: 列號}`。**全部從 1 數**。要分深淺再加 `v:`（見下） |
| `mark` | **v1.6 選用**。`both`（預設，v1.5 行為：兩格都上底色）／`max`（**只標數值較大的那一格**）。兩格數值相同時兩格都標 |
| `note` | 預設 `true`：備註自動補上引擎提供的標準句「**底色著色為經統計檢定有顯著差異，方向為上下（／左右）著色**」；`mark: max` 時前半自動換成「**…，左右（／上下）配對中只標數值較大的一格**」，有分深淺時後面再接一句深淺說明；要自己寫就設 `false` |
| `scale` | **分深淺時必填**（v1.6）：強度值是哪一種統計量，例 `"|t|"`、`"-log10(p)"`、`"Cohen's d"`。會印進備註與 tooltip |
| `levels` | **分深淺時必填**（v1.6）：兩個切點（由小到大、非負），例 `[2.58, 3.29]`。階數固定三階，不開放調 |

**`mark` 與深淺分級是正交的兩件事**：`mark` 決定**哪一格**上色、`scale`／`levels` ＋ 每組的 `v`
決定**那一格多深**。可以只用其中一個，也可以併用（併用＝只有較大那格上色、深淺依檢定強度）。

**`mark: max`（v1.6）**：Lena 2026-09-16 定案「兩格單純比較只需要把數值大的著底色」。

```
sig:
  dir: lr
  mark: max               # 一組配對只標數值較大的一格
  pairs:
    - {row: 1, a: 2, b: 3}
```

大小怎麼比：優先用該格的排序值（`顯示@@排序值` 的右半），沒寫排序值就從 `{{d:…}}`／`{{n:…}}`
裡挖數值，再去掉千分位、`%`、`pp` 與全形正負號。**讀不出數字會報錯**（`N/A`、`—`、`ns` 這種），
修法是給那一格補 `顯示@@數值`，或把 `mark` 改回 `both`。

**併用寫法**（只標較大那格、深淺依 `|t|`）：

```
sig:
  dir: lr
  mark: max
  scale: "|t|"
  levels: [2.58, 3.29]
  pairs:
    - {row: 1, a: 2, b: 3, v: 5.91}     # 較大那格上第 3 階
    - {row: 2, a: 2, b: 3, v: 2.12}     # 較大那格上第 1 階
```

- 標準備註句由引擎產生，內容檔**一行都不用寫**（宣告 `sig` 就有）。
- 列印／轉 PDF 底色不會掉（inline `print-color-adjust: exact`）；底色只有亮度差、色盲安全。
- 每個上底色的格子帶 `data-sig="1"` 與 `title` 提示（螢幕閱讀器讀得到）。
- `dir: tb` 的表會**自動關掉排序**（排序會把上下相鄰的兩格拆開）；`dir: lr` 不受影響，照樣可排序。

#### 深淺三階（v1.6）：`v`／`scale`／`levels`

`pairs` 每一組帶一個 `v`（這組配對的**檢定強度**，非負）就會依強度上深淺；**一組都不帶 `v` ＝ v1.5 的單一階，
輸出逐 byte 不變**。三階的色值與明度（同一個藍色相，只動明度）：

| 階 | 色值 | CIE L\* | 灰階 luma | 什麼時候用到 |
|---|---|---|---|---|
| 第 1 階（最淡） | `#d7e3ee` | 89.6 | 225 | `v < levels[0]`，＝v1.5 那個單一色 |
| 第 2 階 | `#b0c8db` | 79.4 | 196 | `levels[0] ≤ v < levels[1]` |
| 第 3 階（最深） | `#8baec9` | 69.5 | 169 | `v ≥ levels[1]` |

```
sig:
  dir: lr
  scale: "|t|"              # 強度值是哪一種統計量（必填，會印進備註）
  levels: [2.58, 3.29]      # 兩個切點（必填，由小到大）；這組＝大樣本下的 p<.01／p<.001
  pairs:
    - {row: 1, a: 2, b: 3, v: 5.91}    # |t| 5.91 → 第 3 階（最深）
    - {row: 2, a: 2, b: 3, v: 3.04}    # → 第 2 階
    - {row: 3, a: 2, b: 3, v: 2.12}    # → 第 1 階（最淡）
```

- **只有三階，不開放調階數**：白底再加三階剛好每階差 10 個 L\*，四階以上在灰階列印／影印時會糊在一起
  （這是把 v1.5「只做單階」翻案時的交換條件，見 風格B設計決定.md 決定 36）。`levels` 給一個或三個切點會報錯。
- **`scale` 與 `levels` 都必填，引擎不猜**：同樣是 3.0，`|t|` 是普通顯著、`-log10(p)` 已經是 p=0.001。
  猜錯會讓讀者把弱證據看成強證據，所以寧可報錯。常用的兩組：`|t|` → `[2.58, 3.29]`；`-log10(p)` → `[2, 3]`（＝p<.01／p<.001）。
- **階界是絕對門檻，不是這張表的 min／max**（和 cohort／`sigheat` 熱圖不同）。好處是**同一份報告的多張表可以互相比深淺**；
  代價是階界要自己訂——同一份報告請固定用同一組 `scale` 與 `levels`。
- `v` 一律**非負**（`|t|`／`-log10(p)`／效果量絕對值，全表同一種，沿用 `sigheat` 的規矩）；填負數、非數字、
  或只有一部分 `pairs` 帶 `v` 都會報錯並指行號。
- **深淺只編碼「證據多強」，不編碼方向、也不編碼幅度**。方向看 `{{d:…}}` 的 ▲▼ 與正負號；
  幅度看變化欄。n 夠大時什麼都會顯著，`|t|` 大 ≠ 差很多，這點請寫進判讀。
- **原始統計量仍然要留一欄**（`p 值` 或 `|t|`）：底色是輔助線索，黑白影印或色盲的讀者要能從數字讀出同一件事。
  每個上色格的 `title` 也會帶「`|t|`＝5.91（第 3 階／共 3 階，越深證據越強）」。
- **底色只上在被比較的那兩個數值格**，不要上在 `{{d:…}}` 變化欄——紅綠字壓在第 2／3 階底色上，對比只剩 3.3／2.4，
  低於 WCAG AA。`{{n:}}`、純數字、`{{v:}}` 都沒問題（墨色在最深階仍有 8.1）。
- 同一格被兩組配對指到（A vs B、A vs C）時**取最深的那一階**，不報錯。
- 上了深淺的格子多帶一個 `data-sig-lv="1|2|3"`；沒分階的格子屬性與 v1.5 完全相同。

### 5.2 `rowspan`／`row_groups` — 合併格與列群組粗框（v1.5）

v1.4 之前只能用「第一列寫、其餘留空」與「插一列灰底群組名」近似，v1.5 是真的做。

```
rowspan: [1]              # 第 1 欄相鄰同值的列合併成一格
row_groups: [2, 2, 2]     # 由上往下：2 列一群、2 列一群、2 列一群（加總＝資料列數）
```

| 欄位 | 說明 |
|---|---|
| `rowspan` | 欄號清單（從 1 數）。同一欄**相鄰且同值**的列合併成一格（空白格不合併）。寫多欄時是**階層式**：後一欄的合併不會跨過前一欄的分界 |
| `row_groups` | 每一群有幾列，由上往下寫，**加總要剛好等於資料列數**。群與群之間畫一條 2px 粗線，最後一群底下也收一條 |
| `col_groups` | （v1.9）每一群有幾欄，由左往右寫，**加總要剛好等於欄數**。群與群之間畫一條 2px 直粗線，**最右邊不收線**。用來把「同一個指標的 前／後／變化%」框成一塊。`col_groups` 綁的是欄、排序只重排列，所以它**不會**把表格變成固定列序 |

- 兩者都**綁在列的位置**上，所以宣告了就**自動 `sortable: false`**（排序會把合併格與群組打散）；
  故意寫 `sortable: true` 會報錯。這種表在 HTML 上帶 `data-fixed="1"`，`qa_html.py` 第 11 項認得、不會當成缺排序。
- 合併後第一欄的 `<th>` 會自動改成 `scope="rowgroup"`（無障礙）。
- 粗框沿用 `--line` 色票只加粗，**沒有新 CSS**（走 inline style）。

## 6. 數字 `{{v:key}}`

來源兩處，可混用、key 不能重複：

```
---
values_file: data/values.json          # {"key": "值", …}
values:
  斷點: 2026-08-12                     # 純文字
  前段人日: "648,213"                  # 含逗號要引號
  組內效應: {{d:-1.20: 分}}             # 直接寫 chip 標記
  前段平均: {fn: mean, fig: ts_break, col: raw, seg: pre, fmt: n, nd: 2, unit: 分}
  平均變化率: {fn: pct_change, fig: ts_break, col: raw, a: pre, b: post, fmt: d, nd: 1, unit: "%"}
  週最高: {fn: max, fig: dow, col: 星期效應, fmt: d, nd: 2, unit: " 分"}
---
```

### 計算式（刻意只做這幾個，不是通用算式引擎）

| `fn` | 算什麼 | 範圍參數 |
|---|---|---|
| `mean` `sum` `min` `max` `range` `count` `first` `last` | 一段資料的統計量 | `seg: pre/post/all`（預設 all）或 `from`／`to`（x 值） |
| `diff` | `b − a` | `a`、`b`：`pre`／`post`／`all`（取該段平均）、`first`／`last`（端點）、或 x 值（該點）。預設 a=pre、b=post |
| `pct_change` | `(b / a − 1) × 100` | 同上 |

- `fig`：要引用的圖 key（該圖必須有資料：line／bars／ranked／stacked100／waterfall／retention／grouped／funnel／stacked／cohort 的欄）。
- `col`：欄名；圖只有一欄時可省。ranked 與 stacked 另有 `total` 欄；waterfall 的欄叫 `value`；cohort 的欄叫 `D1`、`D7`…（有缺值的範圍會報錯，用 from／to 避開）。
- `seg` 的 pre／post 以該圖的 `break` 為界，**斷點當日不計入兩段**（沿用 v3 口徑）。沒宣告 break 就不能用 pre／post。

### 格式

| `fmt` | 產出 | 例 |
|---|---|---|
| `n`（預設） | `{{n:值:單位}}` 中性數字 chip | `{{n:39.05:分}}` |
| `d` | `{{d:±值:單位}}` 變化量 chip，自帶正負號與 ▲▼ | `{{d:-12.1:%}}` |
| `text` | 純文字 值＋單位 | `648,213` |

`nd` 小數位（預設 1）、`unit` 單位（要有前置空格就寫 `" 分"`）、`comma: true` 千分位。

`python3 scripts/build.py --md 報告內容.md --keys` 會列出所有 key、目前的值與來源。
