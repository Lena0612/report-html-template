# 內容檔格式說明（skill v1.6，2026-09-16；承 v3 定稿）

這份 HTML 報告的**文字、圖表宣告、數字來源**全部在一份 `報告內容.md`；圖表的資料放旁邊的 `data/`。
跑一行指令就重新產出 HTML。版型、字級、顏色、互動都不在這裡改（見 `風格B設計決定.md`）。

跟 v3（2026-09-14 上午交付）差在哪：v3 的圖表與數字寫死在 `content_playtime.py`（要 numpy）；skill 版改成
```` ```figure ````／```` ```table ```` 區塊宣告 ＋ csv／json 資料 ＋ 檔頭 `values:`，純 Python 標準庫。
`{{fig:key}}`／`{{tbl:key}}` 兩個舊標記停用，其餘寫法不變。

---

## 1. 檔案在做什麼

| 檔案 | 內容 | 誰改 |
|---|---|---|
| `報告內容.md` | 標題、前言、結論、建議、各章文字、判讀、附錄 ＋ 圖表宣告 ＋ 數字定義 | **妳／Claude** |
| `data/*.csv`、`data/values.json` | 圖表資料、表格資料、手寫的數字 | **妳／Claude** |
| `scripts/figures.py` | 讀宣告 → 畫圖／組表／算數字 | 引擎 |
| `scripts/rhtml.py` / `themes.py` / `svgchart.py` | 版型、字級、顏色、互動、畫法 | 引擎（鎖定） |

版型順序寫死：**標題 → 前言 → 結論 → 建議 → 各章 → 附錄**。md 裡區塊的先後不影響它。

---

## 2. 怎麼產出 HTML

```
python3 scripts/build.py --md 報告內容.md --out 輸出資料夾/     # 檔名用 title
python3 scripts/build.py --md 報告內容.md --keys               # 列出所有 {{v:key}} 與圖表 key
python3 scripts/build.py --types                              # 列出圖表類型與欄位
python3 scripts/qa_html.py 輸出資料夾/報告.html                 # 17 項自我檢查
```

**寫錯不會產出壞檔案**：解析不過就印「第幾行、什麼問題、提示」、exit 1，既有 HTML 不動。
根因（圖表宣告／資料層）會先列，正文層的連鎖錯誤放後面。

## 3. 檔頭（最上面 `---` 之間）

| 欄位 | 放什麼 | 出現在哪 |
|---|---|---|
| `title` | 「遊戲名－議題」 | 大標（H1）、瀏覽器頁籤 |
| `subtitle` | 副標（**v1.9 起選填**；不寫＝那一行整個不出現） | 大標底下一行 |
| `period` | 資料時間區間、斷點、前後段天數 | 標題區底下的淡字資料說明 |
| `population` | 母體與 n | 同上 |
| `source` | 資料來源（表名／notebook） | 同上 |
| `produced` | 產出日期 `YYYY-MM-DD`（**v1.9 起選填**；不寫＝資料說明少一項，前面那根 `｜` 也跟著少） | 同上 |
| `byline` | `數據分析一組 \| Lena` | 大標上方小字 |
| `disclaimer` | 示意假資料標記；**正式報告整行刪掉** | 紅框小標 ＋ 列印水印 |
| `badge` | 樣張標籤；正式報告整行刪掉 | 資料說明底下灰字 |
| `note_base` | 全篇圖表共用的母體註腳「母體：…｜口徑：…｜n：…」（選填；**v1.9 起不寫、圖表也沒寫 `note`／`note_extra` 時，備註那一段整塊不渲染**，不會留一個空的 `<p>`） | 每張圖表的備註下方 |
| `values_file` | `data/values.json`（`{"key": "值"}`） | — |
| `values:` | 底下縮排寫 `key: 值` 或計算式 | — |
| `appendix` | **v1.5**：`appendix: false` ＝ 這份不要附錄。整節不出現、目錄跟著少一項、也不會留空標題 | 附錄那一節 |
| `hints` | **v1.5**：`hints: false` ＝ 不印圖表標題旁的互動提示小字 | 圖表標題右邊 |
| `conclusion_lead` | **v1.9**：`conclusion_lead: false` ＝ 不印「紅＝漲、綠＝跌，▲▼ 與正負號同步。」那行小字 | 結論標題底下 |
| `conclusion_badge` | **v1.9**：`conclusion_badge: false` ＝ 不印結論標題旁那顆「最重要」膠囊（4px 紅上框與 icon 紅色會原樣保留） | 結論區塊標題 |
| `conclusion_box` | **v1.9**：`conclusion_box: true` ＝ 結論每一條各自一個灰底區塊；標 `[up]` 的那條改紅底紅字。要配 `conclusion_style: list`／`numbered` | 結論區 |

- `appendix: false` 時**不可以**再寫一節 `## 附錄`（會報錯，二選一）；不寫這個欄位＝照舊要有附錄。
- `hints: false` 關掉的只有三種提示小字（「可互動：滑過看數值」「點欄位可排序（點第三次回原順）」
  「窄螢幕可左右捲動看完整張圖」）。**排序、滑過看數值、序列開關這些互動照樣可以用**，只是不印字。
- **必填只剩五個**：`title`、`period`、`population`、`source`、`byline`（v1.9 起 `subtitle` 與 `produced` 改選填）。
  `subtitle`、`produced`、`disclaimer`、`badge`、`note_base`、`values_file`、`values` 都可不寫；
  **不寫就是那一塊整個不渲染**，不會印空字串、也不會留一個空的 `<p>`／空的分隔線。
  `note`／`note_extra` 寫了 key 卻留空值會報錯（要嘛寫內容、要嘛整行拿掉）。
- 檔頭欄位裡可以用 `{{v:…}}`（`period`、`population` 通常這樣寫）。
- 值裡有 `,`／`:`／`#` 或前後空格 → 用雙引號包（`note_base: "母體：…｜n：前段 648,213 user-day…"`）。

## 4. 區塊：`##` 開頭

```
## 前言
## 結論
## 建議
## 現象確認：真的掉了，型態是水位跳動      ← 這種就是「第 1 章」
## 附錄
## 本版說明                                 ← 樣張用；正式報告不要放
```

- 保留字：`前言`、`結論`、`建議`、`附錄`、`本版說明`。其他 `##` 一律當章節，依序自動編號；目錄與圖表編號跟著變。
- `###` 是子節（H3）。不要用單一個 `#`。

## 5. 前言

第一段排成大字 lede，2～3 句「這份在看什麼、掉多少、下面怎麼展開」。同一段可換行寫，空一行才換段。

## 6. 結論（固定清單語法）

```
- [dn] 平均遊戲時間由 {{v:前段平均}} 降到 {{v:後段平均}}（[[ts_break]]）。
- [up] 買量新客占 user-day 比重 {{v:買量占比前}} → {{v:買量占比後}}（[[mixbar]]）。
- 星期效應校正後結論不變（[[dow]]）。            ← 不寫方括號＝灰色（中性）
```

| 寫法 | 顏色 | 用在 |
|---|---|---|
| `[dn]`（或 `[跌]`／`[綠]`） | 綠 | 這條講的是下降 |
| `[up]`（或 `[漲]`／`[紅]`） | 紅 | 這條講的是上升 |
| 不寫 | 灰 | 中性、沒有方向 |

> 結論卡 tone 為人工指定；紅同時代表「漲」與「重點」，Lena 2026-09-10 決定維持。

**v1.5：結論也可以放表格**（條狀卡片仍然是預設）。在 `## 結論` 裡直接寫 ```` ```table ````
（```` ```figure ```` 也可以）區塊就好：

```
## 結論

```table
key: concl_tbl
title: 跌點盤點（診斷、變化與歸因推測）
columns: [跌點, 診斷, 主要變化, 歸因推測]
data: data/concl.csv
defs:
  維度: …
  指標: …
  著色: …
```

- [dn] 平均遊戲時間後段少 {{v:主跌幅}}，經檢定顯著（見 [[concl_tbl]]）
- [dn] 高底台跌最多，是全站跌幅的主要來源
```

- **卡片是預設、不能拿掉**：至少要有一條 `- 一句話`（表格是加在卡片之外的，不是取代）。
- 位置：區塊寫在**第一張卡片之前**就排在卡片上方，寫在卡片之後就排在下方。
- 編號：結論裡的圖表編號是 **`表 C-1`／`圖 C-1`**（C＝Conclusion，比照附錄的 `A`），
  不佔用章節的 `1-1`，讀者一看就知道它在結論、不在第 1 章。
- 其餘規矩跟章節裡一樣：`defs` 三行、母體註腳、**至少被 `[[key]]` 提到一次**（QA 第 4 項），
  收尾 ``` 的下一行可以寫 `判讀：`。

**v1.7：結論可以改成純條列**（不是條狀卡片）。在檔頭寫 `conclusion_style: list`：

```
---
…
conclusion_style: list         ← 不寫＝card（條狀卡片，v1～v1.6 行為）
---

## 結論

- [dn] 6/2 與 7/1 各跌一階（[[ts99]]）
　◦ 牌桌參與率不變，掉的是人均手數（[[m21_0602]]）      ← 全形空白 ＋ ◦ ＝上一條的子項
　◦ 分布整段平移，不是只有重度玩家在掉（[[m22_0602]]）
- [dn] 7/1 牌桌與機台一起掉（[[c1_0701]]）
```

- 只有 `conclusion_style: list` 時才吃 `◦` 子項；**卡片模式下 `◦` 開頭的行仍然是「上一條寫太長的換行接續」**
  （v1.6 行為不變）。子項只有一層，再深的層次請改寫成表格。
- 第一條就寫 `◦`（上面沒有主條目）會報錯、不產 HTML。
- `[dn]`／`[up]` 在條列模式只寫進 `class`、不上色——條列沒有卡片上緣那條色帶；方向仍然看 ▲▼ 與正負號。
- Lena 2026-09-16 16:06：「結論用條列式，不是卡片」。要卡片就把檔頭那行拿掉。

**v1.9：結論每一條各自一個區塊**。`conclusion_style: numbered`（或 `list`）再加 `conclusion_box: true`：

```
conclusion_style: numbered
conclusion_lead: false        ← 不印「紅＝漲、綠＝跌…」那行
conclusion_badge: false       ← 不印標題旁的「最重要」膠囊
conclusion_box: true          ← 每一條結論各自一個灰底區塊
```

- 灰底是預設；**標 `[up]`（漲／重點）的那一條才是紅底紅字**——沿用既有的 tone 語意，不另外發明標記。
  想讓某一條變紅底，把它的 `[dn]` 改成 `[up]`。
- `◦` 子項**不會**各自再包一個區塊（她要的是「每一點」一個區塊，不是每一行）。
- `conclusion_box: true` 配 `card`（或沒寫 `conclusion_style`）會報錯——卡片本來就是一條一張卡片。
- Lena 2026-09-17 10:18 第 4、5 點：「結論的『紅＝漲、綠＝跌…』、『最重要』刪掉」「結論每一點用一個灰底區塊分隔」。

## 7. 建議（固定清單語法）

```
- [立即] 先對帳 {{v:斷點}} ±3 天的版更／活動／埋點變更清單
  預期影響：決定這份分析成不成立；口徑是第一順位要排除的假說
```

`預期影響：` 那行不能省。方括號是時程標籤（立即／短期／長期，也可寫別的）。不寫負責角色。

## 8. 章節

固定四段：**本章結論 → 一段說明 → 圖表區塊 → 判讀**。

```
## 掉在分布的哪一段：低分位掉最多

本章結論：分布整段平移下移，低分位掉最多（p25 {{v:p25變化率}}、p90 {{v:p90變化率}}）。

只看 mean 分不出「重度玩家流失」與「全體變差」，所以把 p25／p50／p75／p90 與 mean 並列看。

```figure
key: band
type: line
title: 分位數走勢（p25~p75 帶 ＋ p50 ＋ p90 ＋ mean）
data: data/band.csv
…（欄位見 圖表與數值宣告格式.md）
```
判讀：帶寬（p75−p25）前段 {{v:帶寬前}}、後段 {{v:帶寬後}} 幾乎沒變 → 整段平移，不是離散度變大。

```table
key: quant
title: 分位數與 mean 對照（含 mean−median 落差）
data: data/tbl_quant.csv
columns: [統計量, 前段, 後段, Δ, Δ%, 判讀]
…
```
判讀：mean−median 落差 {{v:落差前}} → {{v:落差後}} 沒擴大 → 右尾影響沒變大。
```

| 寫法 | 效果 |
|---|---|
| `本章結論：` | 小標底下粗體帶紅邊的一句（一章一句） |
| ```` ```figure ````／```` ```table ```` 區塊 | 插入圖／表；**區塊放哪，圖就出現在哪**；編號、標題、備註三行、母體註腳自動帶出 |
| `判讀：` | 圖表底下那句判讀，**緊接在區塊收尾 ```` ``` ```` 的下一行**（中間可以空一行，但不能夾別的段落） |
| `標題：` | 區塊收尾下一行寫這個可覆寫圖表標題（通常直接改區塊裡的 `title` 就好） |
| `### 子節標題` | 章節內再分小段（H3） |
| `導言：` | 小標底下的灰色引言（v3 起各章不用） |

- 同一個圖表只宣告一次。別處提到用 `[[key]]` → 自動變「圖 2-1」超連結。**每張圖表至少被提到一次**（QA 第 4 項）。
- 摺疊區塊：`:::摺疊 標題` … `:::`，裡面可放段落與清單、不能放圖表；列印自動展開。

**每張圖表的備註固定四列**（Lena 2026-09-16 15:12 規範，完整判準與反例見 `圖表與數值宣告格式.md` §3.1）：

| 列 | 寫在哪 | 一句話判準 |
|---|---|---|
| 維度 | `defs.維度` | 分群／軸怎麼切——**分群難懂就在這裡解釋**，不要只把欄名唸一遍 |
| 指標 | `defs.指標` | 難理解的指標定義與算法（分子分母、單位、pp 還是 %、檢定門檻） |
| 著色 | `defs.著色` | **只寫這張圖表特有的**：底色／灰底列／空白格／粗框代表什麼。紅漲綠跌這種全報告通用的規則寫在附錄，不要每張都複述 |
| 母體 | 檔頭 `note_base` ＋ 區塊 `note_extra` | 母體 ＋ 口徑 ＋ n ＋ **時間區間**，四樣都要。只寫「玩家」會被退 |

`defs` **只能有這三個鍵**，多寫一個（例如再加 `母體:`）就變五列，`build.py` 會報
「`defs 多了 母體——備註只能四列`」並指行號；`qa_html.py` 第 17 項也會查。

## 9. 行內標記

| 標記 | 產出 | 例 |
|---|---|---|
| `{{v:key}}` | 檔頭 values／values_file 定義的數字（推薦：改資料不會不一致） | `{{v:前段平均}}` → 39.05 分 |
| `{{n:39.1:分}}` | 手寫中性數字（等寬、墨色） | 39.1 分 |
| `{{d:-4.7:分}}` | 手寫變化量，自動配 ▼ 綠／▲ 紅與正負號 | ▼ -4.7 分 |
| `{{warn}}` | **v1.5**：警示 icon（內嵌 SVG 紅色三角驚嘆號）。不吃參數，放在要提醒的那句或那格前面 | |
| `!!重點!!` | 重點紅字（v1.11：一段最多 3 處） | |
| `**粗體**` | 粗體 | |
| `[[key]]` | 引用圖表 → 「圖 2-1」超連結 | |
| 反引號 `` ` `` | 等寬字，裡面的標記不展開 | `` `ns_noEffect` `` |

紅綠是方向不是好壞：紅＝漲／重點、綠＝跌；每個變化數字都帶 ▲▼ 與正負號。

`{{warn}}` 用的是 inline SVG（不是 emoji）：`⚠` U+26A0 屬於 emoji 區段，會被 `qa_html.py` 第 16 項擋下來，
所以警示一律寫 `{{warn}}`。它可以用在正文、結論卡、判讀、表格 cell（csv 裡直接寫）。

## 12. 容易踩到的地方

- 區塊收尾一定要一行只有 ```` ``` ````；區塊裡不能再出現這樣的一行。
- 區塊裡的值含 `,`／`:`／`#` 要用雙引號包；縮排只用空格。
- csv 欄名要跟 `series` 的 `col`／`x` 一字不差；數字不要帶單位與千分位。
- `判讀：` 前面不要夾段落；`本章結論：` 只能在章節裡。
- `!!` 一段最多 3 處（v1.11，Lena 2026-09-17 11:57 放寬；超過會在 build 期報錯＋行號）；
  `**`／`!!`／`{{ }}` 要成對。
- 手寫 `{{n:…}}` 的數字不會跟著資料更新，能用計算式的就用計算式。
- 真資料的正式報告：刪 `disclaimer`、刪 `badge`、不要放 `## 本版說明`。
- v1.5：`appendix: false` 與 `## 附錄` 不能同時存在；`rowspan`／`row_groups`／`sig` 的上下配對不能配 `sortable: true`；
  `xticks` 與 `xtick_every` 只能擇一；`{{warn}}` 不吃參數（`{{warn:red}}` 會報錯）。
- v1.5：`sig` 的列號／欄號都是**從 1 數**，而且是「資料列」的號碼（不含表頭）；
  改了 csv 的列序或欄序，記得回頭改 `sig`／`rowspan`／`row_groups`／`emph_rows`。
- v1.6：`defs` 只能有 維度／指標／著色 三個鍵（備註固定四列，第四列是母體註腳）；多寫一個鍵會報錯。
- v1.6：`sig` 要分深淺就**每一組 `pairs` 都要帶 `v`**，而且 `scale:`（統計量名稱）與 `levels:`（兩個切點）都必填；
  只帶一半、或填帶號 t 值／p 值本身都會報錯。底色不要上在 `{{d:…}}` 變化欄（紅綠字壓在深底色上對比不夠）。
