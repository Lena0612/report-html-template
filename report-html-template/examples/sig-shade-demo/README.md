外加把「備註四列」寫成規範。這份把兩件事湊在一份最小報告裡。
**數字全部是手寫的示意假資料（沒有亂數，重跑一定一樣），不可引用。**
用途：確認 skill 沒改壞、給 Claude 看完整宣告、**給 Lena 列印一張確認三階在紙上分得出來**。

## 三階的色值

| 階 | 色值 | CIE L\* | 灰階 luma | 墨色 `#111` 壓在上面的對比 |
|---|---|---|---|---|
| 第 1 階（最淡） | `#d7e3ee` | 89.6 | 225 | 14.49 |
| 第 2 階 | `#b0c8db` | 79.4 | 196 | 10.91 |
| 第 3 階（最深） | `#8baec9` | 69.5 | 169 | 8.09 |

白底 L\* 100 → 三階 89.6／79.4／69.5，**每階差約 10 個 L\***（加白底剛好四級等距）；
灰階相鄰對比 1.33／1.35。protan／deutan／tritan 模擬後明度序不變（只動明度，不動色相）。

## 看什麼

- **三階怎麼分的**：`levels: [2.58, 3.29]` 是**人訂的絕對階界**（大樣本下 p<.01 與 p<.001 的 z 門檻），
  不是這張表的 min／max——所以兩張表的深淺可以直接互相比。`sig_lr` 的 |t| 5.91／3.04／2.12 剛好落在三個階。
- **`scale` 與 `levels` 都必填**：同樣是 3.0，`|t|` 只是普通顯著、`-log10(p)` 已經是 p=0.001。
  引擎不猜，缺了就報錯。
- **不帶 `v` ＝ 完全是 v1.5**：`charts-demo-5` 兩張 `sig` 表都沒帶強度值，輸出逐 byte 不變。
- **底色只上在被比較的兩個數值格**，沒有上在 `{{d:…}}` 變化欄——紅綠字壓在第 2／3 階底色上對比只剩 3.25／2.41，
  低於 WCAG AA；墨色數字在最深階還有 8.09（AAA）。
- **原始統計量留一欄**：兩張表都把 `|t|` 印出來。底色是輔助線索，黑白影印與色盲的讀者要能從數字讀到同一件事；
  每個上色格的 `title` 也帶「`|t|`＝5.91（第 3 階／共 3 階，越深證據越強）」。
- **備註四列的新寫法**：著色那列**只寫這張表特有的**（階界、沒上底色是什麼意思），
  紅漲綠跌改寫在附錄「圖表色彩規則」講一次——對照 `charts-demo-5` 的舊寫法（每張表都複述一次）。
  母體那列（`note_base`）四樣齊全：母體 ＋ 口徑 ＋ n ＋ **時間區間**。
- **hierarchical rowspan**：`rowspan: [1, 6]` 同時合併「底台」與「|t|」兩欄，
  後一欄的合併不會跨過前一欄的分界。

## 與 `charts-demo-6` 的關係（v1.6 合併版）

這份**刻意不宣告 `mark`**，所以每一組配對兩格都上色、只是深淺不同。
`mark: max`（一組只標數值較大的一格）在 `examples/charts-demo-6`。
兩者是**正交**的：`mark` 決定哪一格上色、`scale`／`levels` ＋ `v` 決定那一格多深，
可以只用一個也可以併用；併用的組合案例在 `tests/run_tests.py` 的「B 組合」段。
