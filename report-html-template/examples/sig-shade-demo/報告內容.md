## 前言

這份樣張只為了驗證一件事：表格的檢定顯著底色從 v1.5 的單一階，擴成**依檢定強度分三階**的亮度階（`sig.pairs` 每組帶一個 `v`）。數字全部是手造的示意假資料、不可引用。

三階的色值是 `#d7e3ee`／`#b0c8db`／`#8baec9`——同一個藍色相只動明度，每階差約 10 個 CIE L\*，灰階列印時的 Rec.709 luma 是 225／196／169。**請務必列印一張或轉一次 PDF**，確認三階在紙上分得出來；螢幕分得出來不代表印得出來。

## 結論

- [dn] 平均遊戲時間後段比前段少 {{v:主跌幅}}，是四個指標裡證據最強的一個（見 [[sig_lr]]）
- [dn] 高底台（25/50）跌 {{v:高底台跌幅}}，底色最深＝這一組的證據最強（見 [[sig_tb]]）
- 每局手數沒有通過 p<.05，所以整列都不上底色——**沒有底色不等於沒有差異，是「這份資料還看不出差異」**（見 [[sig_lr]]）
- 三階的階界是人訂的，不是程式自己抓的：這份用 `levels: [2.58, 3.29]`（大樣本下的 p<.01 與 p<.001 門檻）

## 建議

- [立即] 這份樣張列印一次，確認第 1 階（最淡）在紙上還看得見、第 2 階與第 3 階分得出來
  預期影響：確定三階是可用的，不必退回單一階
- [短期] 之後每份報告固定用同一組階界（例如都用 `-log10(p)` 的 [2, 3]），跨報告的深淺才能互相比較
  預期影響：讀者看到「深」就知道大概是什麼量級，不必每張表重新校正
- [長期] 把常用的階界寫進各專案的口徑文件，和顯著門檻一起管理
  預期影響：同一個專案的表不會這張用 |t|、那張用 -log10(p)

## 檢定強度分三階：左右配對

本章結論：四個指標裡三個通過 p<.05，底色依 |t| 分三階，最深的是平均遊戲時間。

底色只上在**被比較的那兩格**（上線前、上線後），不上在變化欄——變化欄是紅綠字，壓在深底色上對比會掉。深淺只編碼「證據多強」，跌多少仍然看變化欄的 ▲▼ 與數字。

```table
key: sig_lr
title: 上線前後對照（底色深淺＝|t| 三階）
columns: [指標, 上線前, 上線後, 變化, "|t|"]
align: [left, right, right, right, right]
types: [text, num, num, num, num]
data: data/sig_lr.csv
sig:
  dir: lr
  scale: "|t|"
  levels: [2.58, 3.29]
  pairs:
    - {row: 1, a: 2, b: 3, v: 5.91}
    - {row: 2, a: 2, b: 3, v: 3.04}
    - {row: 3, a: 2, b: 3, v: 2.12}
defs:
  維度: 四個指標 × 上線前／上線後兩段
  指標: 前後兩段的日平均；付費率的變化用 pp（百分點），其餘用 %
  著色: 階界 2.58／3.29 ＝大樣本下的 p<.01／p<.001；沒上底色＝未達 p<.05（每局手數 |t| 0.84）
note_extra: 檢定：Welch t（雙尾），|t| 為示意值、未實跑
```
判讀：平均遊戲時間 |t| 5.91 上最深的第 3 階、每日開局數 3.04 上第 2 階、付費率 2.12 上最淡的第 1 階。

## 分階與合併格、上下配對併用

本章結論：三個底台各做一次前後檢定，25/50 的證據最強、1/2 沒通過。

上下配對（`dir: tb`）把同一欄相鄰兩列的格子一起上色，深淺規則與左右配對完全一樣。這張表同時開了 `rowspan`（底台欄與 |t| 欄相鄰同值合併，階層式）與 `row_groups`（底台之間 2px 粗線），所以列序固定、沒有排序。

```table
key: sig_tb
title: 底台 × 前後段（合併格 ＋ 上下配對 ＋ 深淺三階）
columns: [底台, 分段, 樣本數, 平均遊戲時間, 變化, "|t|"]
align: [left, left, right, right, right, right]
types: [text, text, num, num, num, num]
data: data/sig_tb.csv
rowspan: [1, 6]
row_groups: [2, 2, 2]
sig:
  dir: tb
  scale: "|t|"
  levels: [2.58, 3.29]
  pairs:
    - {col: 4, a: 3, b: 4, v: 3.12}
    - {col: 4, a: 5, b: 6, v: 6.41}
defs:
  維度: 三個底台（盲注級距）× 前段／後段；同一底台的兩列合併成一群
  指標: 平均遊戲時間（分）＝該段每日平均；變化＝後段減前段
  著色: 階界同上一張表（2.58／3.29）；1/2 底台 |t| 1.07 未達 p<.05，所以整組沒有底色
note_extra: 檢定：Welch t（雙尾），|t| 為示意值、未實跑；|t| 屬於整組配對，兩列合併成一格
```
判讀：25/50 的兩格是第 3 階（最深）、5/10 是第 2 階，1/2 沒有底色——三個底台的深淺差就是「證據強弱」的差。

## 附錄

### 口徑與母體

兩份 csv 都是手寫的示意數字（沒有亂數，重跑一定一樣）。`sig_lr.csv` 是 `指標,上線前,上線後,變化,t` 共 4 列；`sig_tb.csv` 是 `底台,分段,樣本數,平均遊戲時間,變化,t` 共 6 列。兩張表的 `|t|` 都直接印在最後一欄——**底色是輔助線索，原始統計量仍然要有一欄**，讀者才能自己判斷，色盲或黑白列印的人也不必只靠深淺。

### 未驗證與已知瑕疵

- !!全部數字都是示意假資料!!，不是任何真實遊戲的輸出，不可引用、不可做決定。
- `|t|` 沒有實跑任何檢定，是為了示範三階色階手填的；正式報告的 `v` 一定要來自真的跑過的檢定。
- 階界（`levels`）是人訂的：換一組階界，同一份資料的深淺就會變。跨報告比深淺前先確認兩邊用同一組階界與同一種統計量。
- 沒有上底色只代表「這組配對沒有列進 `sig.pairs`」——可能是未達門檻，也可能是根本沒做檢定。兩者的差別要寫在判讀或這一節，色階本身分不出來。
- 樣本數差很多時，|t| 大不等於效果大（n 夠大什麼都會顯著）。要談幅度請看變化欄，不要看底色。

### 圖表色彩規則

- 紅 `#c62828` ＝ 重點與「漲」；綠 `#2e7d32` ＝「跌」（東亞慣例），每個變化數字自帶 ▲▼ 與正負號，顏色不是唯一線索。**這條規則全報告通用，所以每張表的「著色」那列不再重複寫**。
- 檢定顯著底色是中性藍的三階亮度階 `#d7e3ee`／`#b0c8db`／`#8baec9`，**不用紅綠**：底色只說「這兩格差異顯著、證據多強」，不說漲跌。
- 底色走 inline style 並帶 `print-color-adjust: exact`，列印與轉 PDF 都不會掉；沒有新增任何 CSS。

### 互動說明

兩張表都可以滑過上了底色的格子看 tooltip：會顯示配對方向、`|t|` 的值與「第幾階／共三階」。[[sig_lr]] 可以點欄位排序（點第三次回原順）；[[sig_tb]] 有合併格與列群組，**設計上就固定列序、不排序**。觸控裝置 tap 等同 hover；列印時互動停用，底色與粗線照樣印得出來。
