# report-html-b v1.11（2026-09-17）

## 一句話

重點紅字從「**一段最多一處**」放寬成「**一段最多 3 處**」，其餘 16 項 QA 判準一個字沒動。

## 為什麼改

Lena 2026-09-17 11:57 的指示（原話）：

> 改引擎，同一段可以多處紅字，不要分段

起因是印尼合併版 v11 的結論 3 有一句要標兩個重點：

```
貨幣來源主要是少在儲值&獎勵、以「每日任務獎勵_德撲幣」為下跌大宗（佔 52.6%）
```

v1.10 的「一段最多一處」會逼這句拆成兩段。她要的是**維持原句**、句內兩處各自標紅。

## 放寬到多少，為什麼是 3

`HL_MAX = 3`。理由：

1. **實際需要就是 3**：印尼合併版 v11 結論 3 的資產子項是一段三層——
   資產減少（現象）→ 少在儲值&獎勵（來源）→ 每日任務獎勵_德撲幣 52.6%（元凶）。
2. **紅字是「一眼看到哪裡最重要」的工具**。一段超過三處，等於整段都紅、沒有重點，
   跟 v1.0 起「重點紅字克制」的設計意圖直接抵觸。
3. 三處也剛好是一句中文讀起來還能分辨主次的上限。

上限是**硬的**：不是警告、不是建議。build 期擋在前面，qa 期擋在後面。

## 已知限制（沿用 v1.10，這次沒改）

qa 第 6 項的「段」是用 `re.split(r"</p>|</li>", html)` 切的。巢狀清單裡，
**主條目開頭到第一個子項結尾**會被算成同一段（主條目的紅字 ＋ 第一個 `◦` 子項的紅字
會合計）。這是 v1.10 就有的行為，偏保守（寧可誤擋不可漏放），這次刻意**不動**——
要改切段方式是另一件事，不該混在放寬上限裡做。
